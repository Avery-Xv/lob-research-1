# 订单簿形态机制实验：V4 单扫描计算审计说明

## 范围

本实现只验证以下六类同期/条件机制，不进行收益回测，也不拟合
OI01--OI08 的最终预测模型：

1. M1 主动交易同向聚集；
2. M2 上涨状态买侧自刺激；
3. M3 上涨事件刺激集中度；
4. M4 微观高主动强度与盘口深度；
5. M5 日频高热度与平均盘口深度；
6. M6 被动订单成交率的本方/对方强度效应。

## 输入顺序

- V4 已按实际事件顺序存储，本计算器不做沪市事件重排。
- 每个 stock-month 文件按物理顺序流式读取。
- 每个股票日要求 `row_id` 严格递增；发现逆序立即终止，不静默排序。
- 上午和下午是两个独立的日内事件序列，未来事件标签不跨午休。
- 集合竞价不进入查询，`source_side=N` 不进入主动买卖统计。

## 原始 LOB I/O

预热月份字段：

```text
date time row_id source_action source_recid
source_side source_volume bid_px ask_px
```

目标月份字段：

```text
date time row_id source_action source_recid
source_buy_order_id source_sell_order_id
source_side source_price source_volume
bid_px ask_px bid_vol ask_vol
```

明确不读取：

```text
bid_ordvol ask_ordvol bid_cnt ask_cnt source_link_status
```

每个入选 stock-month Parquet 最多打开一次。预热月、目标月使用不同列投影，
所有机制共享同一目标月流。不会生成全市场事件级或订单级 LOB 副本。

## 冻结参数

默认主参数：

| 参数 | 默认值 |
|---|---:|
| 主动强度半衰期 | 5 秒 |
| 半衰期稳健性 | 1、5、30 秒 |
| 正常单笔量 | 过去 500 笔同方向主动成交 |
| 强度高低阈值 | 历史同时段中位数 |
| 未来事件窗口 | 5、10、20、50 个事件 |
| 价格状态窗口 | 10、30、60 秒；主口径 30 秒 |
| 显著涨跌阈值 | 历史波动率的 1.5 倍 |
| 历史分位数容量 | 每股票/时段/方向 5,000 个确定性样本 |
| 历史 profile 抽样 | 每 10 个事件一次 |
| 深度统计抽样 | 每 10 个事件一次 |
| 深度口径 | 一、三、十档；主口径三档 |
| 被动成交期限 | 10、60、300 秒和连续竞价剩余时段 |

所有阈值在进入目标月之前冻结。历史 reservoir 的随机种子由股票代码的
SHA256 确定，因此串行、并行和续跑结果一致。

## 时点定义

- 强度 (I_t) 包含当前事件；平均单笔量只使用当前事件之前的主动成交。
- M1--M3 的未来窗口从当前事件之后开始，恰好在第 N 个后续 LOB 事件完成。
- 未完成的午间和收盘窗口丢弃并计入 `incomplete_future_labels`。
- M4/M5 使用事件发生前的最近有效盘口，因此衡量高强度状态对应的事前可用
  流动性；若审计后需要研究消耗后的盘口，可在同一次目标流中增加 post-book
  版本，无需增加原始文件扫描。
- 深市可成交委托展开为 `ORDER_ADD + TRADE(s)` 时，中间 post-event 快照可能
  暂时交叉；这些行继续计入 `invalid_book` QC，但事件链内的 pre-book 沿用本
  连续竞价时段最近一次未交叉快照，不重排事件，也不把交叉快照当作流动性状态。
- 前收盘使用上一交易日连续竞价最后一个有效中间价。
- 当日开盘使用当日连续竞价首个有效中间价。

## 被动订单口径

- 订单键为 `(side, order_id)`，避免买卖两侧订单号空间碰撞。
- `ORDER_ADD` 记录候选订单及入场时状态。
- `TRADE/B` 的买方订单为主动方，卖方订单累计被动成交量；`TRADE/S` 对称。
- 日终排除所有曾作为主动方出现的订单键，剩余候选订单进入被动样本。
- `CANCEL` 按同侧订单键累计。
- `continuous` 成交标签只覆盖 09:30--11:30、13:00--14:57，不包含收盘集合竞价。
- M6 第一阶段只验证成交率条件关系，不使用队列位置，因而不读取 `ordvol`。

## 输出

每个稳定批次目录包含：

```text
stats.csv       股票日 × 机制 × 变体 × 条件组的 count/sum/sum_sq
quality.csv     股票日数据质量与守恒计数
profiles.jsonl  历史强度、波动率和日热度阈值
audit.jsonl     仅审计模式生成的少量事件和订单轨迹
done.json       批次完成标记
```

分片目录的 `manifest.json` 固定记录：A 股 universe 规则、ETF 数、输入清单及
metadata 哈希、月份、字段投影、排除字段和全部参数。配置指纹不一致时禁止复用
旧分片。

## 审计闸门

全市场提交前必须依次完成：

1. 代码编译和纯合成测试；
2. manifest-only `--dry-run`；
3. `SH600000`、`SZ000001` 各两个交易日的审计计算；
4. 检查事件轨迹、未来 N 窗口和被动订单生命周期；
5. 验证成交量不超过提交量，解释 unmatched passive trades；
6. 串行与并行分片逐字节一致；
7. 45 只预冻结分层股票小样本；
8. 用户再次确认后才提交全 A 股目标月。

截至 2026-08-04 已完成第 1--6 步，并以更严格的 300 只九域分层样本替代原计划
的 45 只小样本。中样本 75 个批次已全部完成；当前仍未启动全市场任务。

中样本的原始分片位于
`data/cache/order_shape_mechanism/medium300_202601_v1/`，总体、九域、时间时钟与
成交事件时钟的结果位于
`results/intraday/order_shape_mechanism/medium300_202601_v1/`。机制结论见其中
`mechanism_findings.md`。

## 两标的真实数据审计结果

- 审计股票：`SH600000`、`SZ000001`；预热 202510--202512，目标月 202601。
- point-in-time A 股 manifest 共 5,188 只股票、20,698 个 stock-month 文件，ETF 为 0。
- 两标的共 40 个股票日、6,530,032 条连续竞价事件；重复成交为 0，
  `fill_over_submit` 为 0，状态历史不足为 0。
- `unmatched_passive_trades=613,343` 的现有字段名容易误解：代码统计的是
  “被动侧订单键不在 M6 候选集合”的成交事件。候选集合只含连续竞价内新出现、
  入场位于 best/near-mid 的订单，因此它包含开盘前遗留单和范围外订单，并不等价于
  v4 订单 ID 链接失败；这些成交不会被回填或计入候选订单成交量。
- 深市一笔可成交委托展开为 `ORDER_ADD + TRADE(s)` 时会出现暂时交叉的
  post-event 快照。`SZ000001` 共 311,256 条，保留为 `invalid_book` QC；
  沿用最近有效 pre-book 后，`invalid_prebook` 从 30,995 降为 40。
- 串行与双进程并行的两个 batch 共 10 个产物文件 SHA-256 逐字节一致，
  manifest 配置及指纹 `6ffe873d15a047f1630acb9c01a5efdbd9186788f00ff7e49fbdcc8d270dc60c` 一致。
- 审计汇总位于 `results/intraday/order_shape_mechanism_audit_202601_v2/`。
  两标的结果只用于确认代码路径和机制方向，不作为全市场统计结论。
